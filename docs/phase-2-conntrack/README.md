# Phase 2 — conntrack production-readiness + eBPF-переносимость (ядро 6.17)

> **Цель Фазы 2:** довести **conntrack** (eBPF-трекинг соединений) до
> production-ready состояния — по образцу того, что уже сделано для **netmon** в
> [Фазе 1](../completed/prod-readiness/README.md) — и параллельно устранить
> **проблему переносимости eBPF на ядро 6.17** (и уже известный баг conntrack на
> 6.8/6.12). Владелец предоставит виртуальную машину с ядром **6.17** для тестов.

> Эта фаза **заменяет** отложенные пункты `C-1…C-7` из
> [`APPENDIX-conntrack-later.md`](../completed/prod-readiness/APPENDIX-conntrack-later.md).
> В скобках у задач указан исходный C-номер.

## Рабочее соглашение (действует для ВСЕХ задач)

**Отдельный PR.** Вся разработка Фазы 2 ведётся в ветке `phase-2-conntrack`
(или её под-ветках) и вливается **отдельным PR**, не смешиваясь с Фазой 1.

**Язык кода/комментариев:** как в окружающем коде (смесь EN/RU). Новые комментарии
в Go — по-английски; допускается русский там, где он уже принят. Не переписывать
стиль соседнего кода.

**Сборка и тесты (из корня репозитория):**
```bash
go build ./...            # собирается без ошибок
go vet ./...              # без предупреждений в изменённых пакетах
go test ./...             # все тесты зелёные
gofmt -l .                # пустой вывод
```
> ⚠️ eBPF-код (`bpf/*.c`, `internal/conntrack`, `pkg/embedded`) собирается только
> под Linux (build tag `linux`). На macOS `go build ./...` берёт заглушки
> `*_other.go`. Изменения eBPF проверяются на Linux-хосте (метка `🐧`), а
> переносимость CO-RE — на ядрах **5.15 / 6.1 / 6.8 / 6.12 / 6.17**.

**eBPF-сборка (на Linux-хосте):**
```bash
make -C bpf all                                   # НЕ bare `make` (он регенерит vmlinux.h)
cp bpf/*.bpf.o pkg/embedded/bpf/                  # обновить embedded-объекты
sudo bpftool prog loadall bpf/conntrack.bpf.o /sys/fs/bpf/_t && sudo rm -rf /sys/fs/bpf/_t
```

**Definition of Done для любой задачи:**
1. `go build ./...`, `go vet ./...` проходят.
2. `go test ./...` зелёный (или явно указаны добавленные/изменённые тесты).
3. `gofmt -l .` пуст.
4. Выполнены все «Критерии приёмки» из файла задачи.
5. Для eBPF-задач: `.o` пересобран из исходников и закоммичен в `pkg/embedded/bpf/`.
6. Не сломаны публичные сигнатуры, используемые в `cmd/netmon/main.go` и
   `cmd/conntrack/main.go`, если задача этого прямо не требует.
7. Изменения минимальны и точечны.

**Что НЕ делать без согласования:**
- Не менять формат/имена существующих Prometheus-метрик (ломает дашборды), кроме
  случаев, прямо описанных в задаче.
- Не удалять существующие HTTP-эндпоинты.
- Не коммитить бинарные артефакты, кроме `pkg/embedded/bpf/*.o`.

## Глоссарий

| Термин | Значение |
|--------|----------|
| **conntrack** | eBPF-трекинг соединений. Живёт как отдельный бинарь `cmd/conntrack` **и** встроен в `netmon` (`cmd/netmon/main.go`). |
| **CO-RE** | Compile Once – Run Everywhere: переносимость eBPF между ядрами через BTF. Ломается, если локальная структура не совпадает с BTF ядра. |
| **`trace_entry`** | Общий 8-байтовый заголовок записи трейспоинта (`type/flags/preempt_count/pid`). В текущем `bpf/vmlinux.h` объявлен неверно (24 байта) — корень багов переносимости. |
| **tracepoint format** | Стабильный ABI записи трейспоинта (`/sys/kernel/tracing/events/<grp>/<name>/format`). Прямое чтение полей ctx по нему не требует CO-RE-релокаций. |
| **ringbuf** | `BPF_MAP_TYPE_RINGBUF` — передача событий из ядра в userspace. |
| **hot-path** | Путь обработки каждого события (ядро → ringbuf → парсинг → метрики). Здесь недопустимы `bpf_printk`, синхронный `/proc`, блокировки. |
| **role/location matcher** | `internal/metadata` — сопоставление IP → роль/локация по маскам из YAML. |
