# TASK-08 — (C-6) Фатальные ошибки без тихой смерти + запрет тихой симуляции в проде

**Метка исполнителя:** 🧠 strong
**Зависит от:** TASK-06 (метрика `up`), связка с TASK-07 (readiness)
**Оценка:** ~0.5–1 день

---

## Контекст (проблема)

1. **Тихая смерть ридера.** `readEvents` при ошибке создания ридера просто логирует
   и выходит (`tracker_linux.go:392-396`), а `Run` блокируется на `<-ctx.Done()` —
   процесс «жив», но данных нет. Нет сигнала наружу.
2. **Тихая симуляция (C-6).** Если eBPF недоступен (`EBPFProgramPath==""`),
   запускается `simulateEvents` (`tracker_linux.go:621-679`) — фейковые
   curl/nginx-соединения каждые 5s. В проде это **незаметно подменяет реальные
   данные фейковыми**.

netmon уже решает (1) через `setFatal(err)` (Фаза 1, TASK-09):
критичная ошибка → `cancel()` → graceful shutdown → `os.Exit(1)`; systemd
рестартует. Некритичные компоненты только логируются.

## Что сделать

1. **Фатальные ошибки коллектора.** Ввести механизм (по образцу netmon
   `setFatal`): фатальная ошибка ридера/attach → выставить `conntrack_collector_up=0`,
   сбросить readiness (`/ready`→503), и:
   - для standalone `cmd/conntrack`: инициировать graceful shutdown + `os.Exit(1)`
     (systemd рестартнёт);
   - для встроенного режима: сообщить наверх (не ронять весь netmon без нужды —
     согласовать с политикой netmon `setFatal`; conntrack — некритичный компонент
     netmon, поэтому там достаточно `up=0` + лог, как для прочих некритичных).
2. **Запрет тихой симуляции в проде.** Поведение при недоступном eBPF:
   - по умолчанию (prod): **ошибка** — `up=0`, `/ready`=503, явный лог «eBPF
     unavailable», НЕ запускать `simulateEvents`;
   - симуляция доступна только по явному флагу, напр. `--simulate` / `dev_mode: true`
     в конфиге. Тогда лог WARN «SIMULATION MODE — synthetic data».
3. Согласовать с TASK-06/07: `up`, `/ready` отражают реальное состояние.

## Критерии приёмки (DoD)
1. При невозможности загрузить/приаттачить eBPF (без флага симуляции) standalone
   conntrack не выдаёт фейковых данных: `up=0`, `/ready`=503, процесс завершается
   ошибкой (или явно сигналит в embedded-режиме).
2. `simulateEvents` запускается **только** при явном флаге/конфиге, с WARN-логом.
3. Тихой смерти ридера нет: фатальная ошибка приводит к `up=0` и видимому сигналу.
4. Нормальный SIGTERM → graceful, код выхода 0.
5. `go build ./... && go test ./... && gofmt -l .` — чисто.

## Как проверить
```bash
# eBPF недоступен, без флага симуляции → ошибка/up=0, не фейк:
sudo ./conntrack --config /etc/conntrack/config.yaml   # ожидаем exit!=0 / up=0, без fake-соединений
# явная симуляция (dev):
./conntrack --config ... --simulate                    # WARN + synthetic events
# нормальная остановка:
sudo systemctl stop conntrack; echo $?                 # 0
```

## Риски
- В embedded-режиме не ронять netmon целиком — conntrack там некритичный
  компонент (сверься с тем, как netmon классифицирует conntrack:
  `cmd/netmon/main.go:356-373`).
- Не сломать тест `TestTracker_Run_ContextCancellation` (он использует
  simulation-режим) — возможно, перевести его на явный флаг симуляции.
