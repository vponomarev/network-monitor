# TASK-10 — (C-5) Поддержка IPv6 в conntrack

**Метка исполнителя:** 🧠 strong 🐧 linux-host
**Зависит от:** TASK-02 (корректные структуры/чтение), TASK-01
**Оценка:** ~1–1.5 дня

---

## Контекст (зачем)

conntrack сейчас обрабатывает только `AF_INET` (IPv4): во всех хуках
`bpf/conntrack.bpf.c` есть ранний выход при `family != AF_INET`
(строки ~162, 228, 340, 413), заголовок программы отмечает, что IPv6 не
реализован (`:26-28`). Адреса хранятся как IPv4-mapped IPv6. Для полноты
нужен трекинг IPv6-соединений.

## Что сделать

1. **eBPF (`bpf/conntrack.bpf.c`):** обрабатывать `AF_INET6` в хуках:
   - читать `saddr_v6[16]`/`daddr_v6[16]` из tracepoint-контекста (поля уже есть
     в структуре после TASK-02) и из `struct sock` (`__sk_common.skc_v6_daddr` и
     т.п.) для kprobe-веток;
   - заполнять адресные поля события корректно для v6 (сейчас v4-mapped).
2. **Go-парсинг (`internal/conntrack/tracker_linux.go`, `types.go`):**
   `IPFromBytes`/`parseConnectionEvent` должны различать v4/v6 и формировать
   правильный `net.IP` (16 байт для v6). Проверить, что `Connection`/ключи
   соединений (`makeConnectionKey`) работают с v6.
3. **Метки/матчинг:** `internal/metadata` должен матчить и IPv6-подсети (проверить
   longest-prefix для v6; при необходимости — задача-предпосылка).
4. Пересобрать `.o`, обновить embedded.

## Критерии приёмки (DoD)
1. IPv6-соединения фиксируются (исходящие как минимум): корректные src/dst v6,
   порты, направление.
2. IPv4 продолжает работать без регрессий.
3. Ключи соединений и метрики корректны для v6.
4. `.o` пересобран/закоммичен; грузится на 6.8/6.12/6.17.
5. `go build ./... && go test ./... && gofmt -l .` — чисто.

## Как проверить
```bash
make -C bpf all && sudo bpftool prog loadall bpf/conntrack.bpf.o /sys/fs/bpf/_c && sudo rm -rf /sys/fs/bpf/_c
# создать IPv6-соединение и убедиться, что оно появилось:
curl -6 -s http://[::1]:.../  # или к внешнему v6-адресу
```
