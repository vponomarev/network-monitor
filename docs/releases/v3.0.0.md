# Release v3.0.0

This release corrects TCP lifecycle accounting and path-discovery measurements,
hardens installation and metadata reload, and adds Linux regression coverage.
It is a major release because discovery JSON and reload behavior have changed.
Published binaries support **Linux amd64 only**.

## Upgrade notes

- Replace conntrack and any explicitly configured external eBPF object together.
  The socket-identity/event ABI has changed; the single binary embeds its matching
  object. Old external objects are rejected at startup.
- Metadata reload refreshes the contents of existing files. Changing config.yaml,
  including metadata paths, URLs or polling intervals, now requires a restart.
  Invalid metadata leaves the previous active data intact.
- Successful metadata reload starts a new loss-counter epoch. Prometheus
  `rate`/`increase` handles counter resets; historical counts are no longer
  relabelled using one representative address.
- Discovery JSON replaces `total_loss` with `destination_probe_loss_percent`.
  Null means no destination measurement is available. This measures missing
  ICMP replies, not proven forwarding loss. Intermediate ICMP suppression no
  longer produces a claimed bottleneck. Update API consumers accordingly.
- Discovery `loss_count` and `loss_rate` cover the configured window, using 64
  bounded time buckets. Traceroute source addresses must be local to the host.
- New configurations bind HTTP to `127.0.0.1`. For remote scraping/API access,
  explicitly configure a bind address, Bearer token and network ACLs. Existing
  configuration files are preserved.
- DNS monitoring uses the system resolver. When enabled, `interfaces` must be
  empty and `port` must be 53 or omitted.

## Fixes

- Separate both sides of loopback connections and identical tuples in different
  network namespaces; preserve socket generations and correct process identity.
- Keep live established sockets beyond the state TTL, measure handshake in the
  kernel, and expose connection starts and failures.
- Reject startup when a required incoming probe cannot attach. Bound remote
  syslog I/O and safely stop its queue and timeout callbacks.
- Bound discovery pair/path storage, return independent snapshots, correct
  windowed rates, and refresh periodic probes instead of serving stale cache.
- Correlate ICMP responses using probe identity, destination and payload; bind
  probes to the requested local source.
- Validate intervals and timeouts, support IPv6 HTTP bind, honor log output
  paths, and publish optional monitor snapshots at `GET /api/v1/monitoring`.
- Correct topology default-route matching and graph traversal, and handle
  bandwidth counter resets without unsigned underflow.
- Verify downloads before atomic binary replacement, preserve user configs,
  use version-matched release bundles, and prepare required systemd directories.
- Rebuild embedded eBPF for production make targets. Release builds use Go
  1.26.7 and run tests, vet and vulnerability checks before packaging.

## Validation

Go race tests, vet, lint and vulnerability checks are required before release.
Linux lifecycle, namespace isolation, ICMP, delayed-handshake and TCP-loss
regressions are qualified on these actual kernels:

- `5.15.0-190-generic`
- `6.1.0-45-amd64`
- `6.8.12-20-pve`
- `6.12.96+deb13-amd64`

## Install or upgrade

Download the desired Linux amd64 bundle and `checksums.txt` from this release.
Verify downloads before extraction:

```sh
sha256sum -c checksums.txt --ignore-missing
tar -xzf netmon-v3.0.0-linux-amd64.tar.gz
```

Back up the existing binary, configuration and unit before upgrading. Preserve
existing `/etc/netmon/*.yaml` files; copy examples only for missing files. Stop
the service before replacing a running binary, install the matching unit, run
`systemctl daemon-reload`, restart and check `/ready` and `/metrics`. Restore the
backup if startup fails. Review the compatibility changes above before rollout.

Assets include netmon and conntrack runnable bundles and raw binaries,
`irqdiag-linux-amd64`, and SHA-256 checksums. Conntrack also supports its built-in
`install` and `rollback` commands.
